# Jisr M3: guest journey (Profile → Matches → Program), implementation plan

> Task-level plan for approval. Bite-sized TDD steps and exact code per task are written per task at execution time (after the M3-T0 design gate), following the same brief format as `2026-09-29-foundation-*`. Execution: `superpowers:subagent-driven-development` (implementer Sonnet 5.5 high, reviewer Opus 5.5 medium on every task, planner Opus for architecture-heavy tasks).

**Goal.** A Moroccan Bac holder opens Jisr on a phone, in fr, en or ar, and with no server call and no account: builds a profile stored only in localStorage, sees programs grouped ✅ / ⚠️ / foundation ⚠️ / ❌ with honest reasons, costs and deadlines, and opens a statically generated program page where every fact carries its source. The journey is covered by Playwright in fr and ar, phone and desktop.

## Decisions taken on the open questions (2026-09-30, product-owner delegated: "choose the best approach")
1. **Budget currency / MAD.** Budget is entered in EUR (MAD selectable but explained as "cannot be compared yet"); no MAD conversion in M3 until a sourced exchange-rate fact exists in `data/` (inventing a rate would break "no invented data").
2. **Digits in Arabic.** Latin digits (Moroccan usage; `ar-MA` with `numberingSystem: "latn"`).
3. **❌ programs.** Shown in a collapsed group at the end with the count visible (transparency is the product).
4. **Origin preselection.** When exactly one origin exists in the data (MA), preselect it for nationality and credential country, editable; the model stays origin-agnostic.
Also decided in ADR 0005 (already merged on this branch): mobile-first with designed desktop layouts; decisive ❌ stands; certificate choice constrained to the rule's language; tuition official single fee or null.

## Architecture decisions
**(1) Data access is a hybrid with a precise boundary.**
- **Program pages are generated at build time**: `/[locale]/programs/[slug]` uses `generateStaticParams`, `dynamicParams = false`, reading `public/snapshots` through `src/lib/snapshot/server.ts` (`import "server-only"`, `fs`, build time only; `pnpm build` already runs `data:build` first). Build-time HTML contains only facts independent of time and of the student: name, institution, city, degree, duration, teaching languages, summary, tuition value, intake dates as published, application channel, documents, each requirement rule described in general terms (not evaluated), cost ranges without a budget, linked and destination scholarships, official links, and the static part of each SourceBadge (info kind, link, verified date DD/MM/YYYY).
- **Anything depending on the clock or the profile is a client leaf** with a neutral server placeholder (no hydration mismatch): freshness marks and the page-level aging/stale banner (computed from the browser's `now`, so an old build never claims to be fresh), next deadline (upcoming/closed), the personal match, route, reasons, budget fit, nationality-filtered scholarships.
- **Profile and Matches are static shells with client islands** using the client loader.
- **Client loader `src/lib/snapshot/`**: manifest fetched `cache: "no-cache"` and validated with `ManifestSchema`; shards fetched by manifest name; the trust boundary is integrity, not Zod: byte length, then SHA-256 via `crypto.subtle` (fallback to length check + dev warning when `subtle` is missing), then a structural guard (`kind`, destination/field/locale match the shard name). In-memory `Map` per session + HTTP cache; `next.config.ts` `headers()` sets `/snapshots/s/*` to `immutable, max-age=31536000` and `/snapshots/manifest.json` to `no-cache`. One manifest per session and every bundle is resolved from a single manifest; on a shard 404 refetch the manifest once, drop the cache and rebuild the whole bundle if the version changed (never mix versions), else show an error state with retry. Base URL `NEXT_PUBLIC_SNAPSHOT_BASE_URL` (default `/snapshots`, ADR 0004: only the manifest URL changes).
- **Shards to load** on Matches: `core`, `routes.<credential.country>`, all destinations × the profile's fields (`programs.*`; destinations are enumerated by parsing the manifest, so destination mismatches count in "N hidden"), plus `institutions`, `costs`, `scholarships` per destination and `text.<locale>.<name>` per structural shard (a missing text shard means empty, not an error). `institutions.<DEST>` is required for "University, City" on cards.
- **Locale text**: `createTextLookup` returns `{text, note}`; note `french_fallback` when `fallback`, `machine_translated` when locale ≠ fr and `status: draft`, else `none`.

**(2) Profile state `src/lib/profile/`**: key `jisr.profile` holds the full `Profile`, parsed with `ProfileSchema` on every read; `schemaVersion` migration table (identity for v1); an invalid/unsupported record is removed and returns `{status:"reset"}` which the UI states plainly; `jisr.profile-draft` holds lenient in-progress form state; `useSyncExternalStore` (server snapshot `unhydrated`, cross-tab via `storage` event); memory fallback + notice if localStorage throws; "Clear my data" control (footer + profile page, with confirmation) removes every `jisr.*` key. The profile is never put in a URL, query string, GET form, log, or anything sent off the device.

**(3) Profile form** (native controls, 4 steps + review, progress indicator, Back/Next never loses data): Step 1 "Your Bac" (nationality; credential country/type/track/status; overall + subject grades on the credential's `gradingScale`, `inputMode="decimal"`, accept `14,5` or `14.5`, inline range check against the scale `[min,max]` shown as "/ 20"; prior higher-education years 0-3); Step 2 "Languages" (fr and en rows always present, more from languages having certificates; level CEFR or "I don't know"; certificate select filtered to `cert.language === row.language`); Step 3 "What you want" (fields ≥1, study languages, destinations (empty = all), institution type); Step 4 "Budget" (optional; amount, currency, month/year; note that budget never hides programs). Native `select`/`input` for mobile pickers and bundle size; shadcn/Radix only where it adds a11y value (AlertDialog for clear data, Collapsible for reasons). Labels on every input, `aria-describedby` errors, focus moves to the step heading, error summary with links, logical utilities only, numeric fields `dir="ltr"`, official names untranslated with gloss.

**(4) Matches page**: groups ✅ `satisfied`; ⚠️ `check` (excluding foundation); ⚠️ foundation (`route==="foundation"`, prominent explanation); ❌ `not_satisfied` (includes `route_not_eligible`, collapsed by default). Order within a group: next upcoming deadline (unknown/closed last), then slug. "N hidden by your preferences" + counts per mismatch + toggle showing them with mismatch reasons. Each card: university, city, degree, languages, tuition (official or "not published, to be checked"), cost total range with the 10-month note, next deadline or "Closed, next dates not yet published", main requirements (top reasons), application method, status badge. Empty states: no profile, `no_programs` ("We are still verifying official data; no programs are published yet"), all hidden, load error with retry. Wording never says "eligible"/"admitted": ✅ reads "Published requirements appear to be met".
**i18n vocabulary** in a `domain` namespace: `domain.status.<MatchStatus>`, `domain.route.<RouteOutcome|missing>`, `domain.reason.{kind,code,outcome}.*`, `domain.checklist.{step,reason}.*` (added now for M4), `domain.mismatch.*`, `domain.cost.{category,per,scope}.*`, `domain.budgetFit.*`, `domain.intake.*`, `domain.infoKind.*`, `domain.freshness.*`, `domain.coverage.*`, `domain.textNote.*`. ICU placeholders only; all three locales; every ⚠️ string says what to check and where; exhaustiveness enforced by a runtime-array + type test.

**(5) Program page** (MVP §3): overview; admission requirements (SourceBadge each, coverage-partial notice, personal match box); tuition; estimated cost of living (`CostBreakdown`); application deadline (client); application procedure (channel name/kind/account needed/summary/link); required documents (translation needed yes/no/unknown); scholarships; official links; last verified; aging/stale banner from the worst freshness across page facts. Desktop: two columns (facts | sticky personal match, deadline, cost); phone: single column, personal box first.

**(6) Shared components** (`useTranslations`, usable in server and client trees; islands receive only needed namespaces via nested `NextIntlClientProvider` + `pickMessages`): `SourceBadge` (+ `FreshnessMark` client leaf), `MatchStatusBadge` (the ONLY place status maps to icon + text + colour, never colour alone), `MatchCard`, `CostBreakdown`, `ReasonList`, `EmptyState`, `LocalizedDataText`, `DeadlineStatus`, `ExternalLink`.

**(7) Scope.** M3 = Profile, Matches, Program page, Home CTA. Everything else is M4 (see end).

**(8) E2E.** Playwright against `next start` on a build of a new synthetic fixture `tests/fixtures/data/e2e-journey` (existing `valid-minimal` stays untouched; `pipeline.test.ts` depends on it); clock pinned with `page.clock`; projects Chromium phone (Pixel 7) and desktop (1280×800), fr and ar as parameters; `@axe-core/playwright` per page; empty state and 404/refetch driven with `page.route`.

**(9) Performance.** Shard gzip ≤ 300 KB already enforced by `data:build`. Initial JS ≤ 150 KB gzipped measured by a Playwright spec summing transferred script bytes on first load of `/fr`, `/fr/profile`, `/fr/matches`, `/fr/programs/<slug>` (ar too); verify with ctx7 whether Next 16 still prints First Load JS. Client Zod is a known cost: measure in T1 and T13; fallback native controls + `zod/mini` for client-only checks.

## Risks
- **Trust semantics leaking into wording or styling (sensitive):** ✅ read as "admitted", an estimate looking official, a missing cost line vanishing from a total, status by colour alone. Mitigation: single mapping sites (T7, `MatchStatusBadge`), wording tests in T4 and T9, reviewer focus.
- **Stale display over time:** build-time pages age silently → freshness, deadlines and banner computed client-side from the browser clock (a wrong device clock shifts them; accepted).
- **Arabic quality:** UI and data ar copy are machine drafts until reviewed (ADR 0005 before-launch item); draft notes shown; track with `TODO-translate`.
- **Hydration:** anything reading localStorage or `todayIso()` is a client leaf with a neutral server snapshot (T6/T12 tests + browser console checks).
- **Snapshot 404 during deploys:** no skew protection relied on; single manifest refetch + whole-bundle rebuild, e2e-tested.
- **Privacy (GDPR / Law 09-08):** MatchResults contain grades and are never logged. Shard request paths reveal credential country, fields and destinations in host access logs (not grades or nationality; nothing reaches analytics); state this in the privacy notice. Alternative: fetch every `routes.*` shard (one origin in Release 1).
- **Performance:** client Zod, Radix, next-intl may exceed 150 KB; measure in T1 and T13; fallback native controls + `zod/mini`.
- **Verify with ctx7 before coding:** Next 16 empty `generateStaticParams` + `dynamicParams=false`; `next.config` `headers()` for `public/` files on Vercel; whether Next 16 prints JS sizes; Vitest TSX without the React plugin; Playwright `page.clock`; `radix-ui` Direction provider export (client component?); next-intl nested providers with `pick`.
- No schema, migration or auth change; snapshot format unchanged.
