### Root cause (why dates and tuition did not move)

1. **`data:pages --topics` is a no-op for Hungary.** `scripts/import/topics.ts` has no `HU` entry in
   `WORDS` (the per-topic search wording) or `LANGUAGE`, and `discoverTopicPages` returns an empty
   map for a country without keywords (`if (words === undefined) return out;`). The institution-level
   fees / deadline / documents / language topic pass therefore sent **no query** for the HU
   institution sites (W1's "88 topic queries" is the query *bound* printed by the summary, not the
   queries sent). Every fee/deadline URL in `pages-hu.json` comes only from the per-programme
   `--search` pass: of the 63 programmes with no tuition, only **9** had any fee page, and 15
   programmes had at most one URL.
2. **The reader's deadlines fail the ADR-0009 international-quote gate.** The reader proposed an
   intake for 37 programmes; **35 were rejected** because the quoted sentence does not name
   international / non-EU applicants — e.g. BME VIK `"Application period in the fall semester: 1st
   April – 15th May"` (the page is headed "For fee-paying applicants", which the gate does not
   accept). The 2 accepted intakes (ELTE International Business, MATE Biochemical Engineering)
   already carry the same official value in `data/`, so enrichment added **none**.

Both gaps stay `null` — nothing was invented, no deadline was guessed and no year was inferred.

**Enabler for a later wave (a code change, outside this wave):** add Hungarian `WORDS`, `LANGUAGE`
and `PATTERN` entries to `scripts/import/topics.ts`, rebuild `pages-hu.json` with
`--topics --topic-list fees,deadline`, then re-run the read. The deadline gate still applies, so the
reader must still find a sentence naming international applicants; a curated national HU deadline
registry (like `pnpm data:fr-calendar`) may be the reliable route for intakes.
