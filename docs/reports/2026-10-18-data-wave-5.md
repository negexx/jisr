# Data wave W5 — scholarships + cost profiles (2026-10-18)

Branch `data/w5-scholarships-costs`, worktree `.worktrees/data-w5-scholarships-costs`, based on
`origin/main` `f0cc00ef`. All work is inside the worktree; `data/` was not modified. The verifier
tools are code + HTTP only (no model), so the OpenCode Go budget was not spent (see Spend).

## Headline

- **Nothing could be staged.** Every target record already exists in `data/`, and both verifiers
  refuse to touch an existing slug: `pnpm data:scholarship verify` returns
  `scholarships/<slug> is already in data/: never overwritten`, and `pnpm data:costs-official verify`
  does the same for cost profiles. There is **no revision/enrich path for scholarships or cost
  profiles** (`data:evidence restage` handles only `programs`; `data:promote --replace-revisions`
  needs a staged file with `_review.revises: true`, which only `restage` writes). This is the wave's
  real blocker; details and remediation below.
- The proposals were therefore run with `--dry-run` (which bypasses the existence guard and still
  re-fetches every quote). What the verifier accepted is listed per record below; those are the
  "staged facts" this wave produces. The proposal JSONs are committed so the promote commands are
  runnable once a revision path exists (or after the owner removes the old record).
- Two of the six scholarships proposed are **rejected by the current verifier** because their
  official pages no longer support the `bachelor` level (or do not name Morocco): the records in
  `data/` are stale relative to the pages.
- **Cost profiles: no line could be staged** — no datable 2026 official figure on an allowed host
  (Task B below). Gaps stay null.

Rejections, with the verifier's own reason:

- `stipendium-hungaricum`: `REJECTED eligibleNationalities: no accepted eligibility quote names MA (the country or its region)` and `REJECTED level: a quote makes this a graduate (master, doctoral) scholarship or requires a bachelor's degree to apply`. The apply/about pages say "bachelor's, master's, one-tier master's and non-degree programmes" (the extra "master's" makes `isGraduateLevel` true) and never name Morocco on the cited pages (Morocco is in the sending-partner annex PDF, not on the pages). Support is dropped too: the stipend clause holds several numbers (`HUF 43,700 (cca EUR 110) … for 12 months`), so no single amount+period clause survives.
- `deutschlandstipendium`: `REJECTED level: no accepted quote says the scholarship itself is for bachelor (undergraduate) students`. The English page now says "First- and higher-semester students of all nationalities…"; it no longer states "Bachelor". The €300/month amount **does** verify (`"300 euros per month for international top-class talent"`). The record in `data/` (promoted 2026-10-05) can no longer be re-confirmed at the bachelor level from this page.
- `fr-excellence-major`: `REJECTED level: no accepted quote says the scholarship itself is for bachelor (undergraduate) students`. The AEFE page states "bacheliers étrangers" (eligibility ✅ via "étrangers") but never "premier cycle"/"licence"/"undergraduate".

Deadlines: **0 staged.** Every scholarship page either states no deadline for international
applicants or states it in a clause that the verifier cannot tie to international applicants (needs
one clause: international naming + exactly one date + a deadline word). `stipendium-hungaricum` does
state `15th January 2026, 2 pm (CET) APPLICATION DEADLINE`, but the clause names no international
applicant, and the scholarship `deadline` field is an ISO date only (no `recurringDeadline` exists in
`ScholarshipRecordSchema`), so the yearless form the brief mentions cannot be stored even if a quote
supported it. This is a schema/verifier gap, not a data gap.

Requirement rules: **0** — the verifier writes `requirements.coverage: partial` with an empty rule
list; scholarships still cannot feed a structured rule. Unchanged by this wave.

## Task B — cost profiles

Owner decision D-4: DE/NL/IT/ES stay Numbeo-link-only — untouched.

- **HU housing + food: no 2026 source on an allowed host.** The only Hungarian cost-of-living figures
  found are on `studyinhungary.hu` (Tempus Public Foundation "costs of living" calculator, 2026-era
  prices) and `stipendiumhungaricum.hu/your-stay-in-hungary/` (40,000 HUF/month housing allowance).
  Neither host is accepted by `isOfficialHost` (the allow-list plus `gov.*` / government suffixes);
  the NAV page (`nav.gov.hu`, allowed) publishes only the health-service contribution already stored.
  So the gap stays null.
- **`fr-paris-official` food: figure exists but is undatable.** The official Campus France
  "Le coût de la vie en France 2026-2027" PDF
  (`maroc.campusfrance.org/.../2026-06/Coût de la vie en France 2026-2027.pdf`, an allowed host)
  states Paris & Île-de-France monthly groceries `"Courses mensuelles entre 220€ et 250€"`. The
  verifier **dropped it**: `dropped food: the quote states no year (a line needs a year of 2026 or
  later in its quote, or in a date quote from the same page)` — the extracted PDF text carries no
  year, so no `dateQuote` is possible and the 2026-only gate rejects the line. Proposal kept for the
  record at `data-staging/proposals-cost-official/fr-paris-official.json`.
- **`fr-paris-official` fees: none Paris-specific.** The VLS-TS validation tax and the CVEC are
  national and already stored on `fr-official`; Paris has no separate fee line.
- **`fr-official`: no gap.** All five lines (housing, food, transport, `application_visa`, `setup`)
  are already present and current.

## Blockers and recommendations

1. **No revision path for scholarships / cost profiles (blocking).** To refresh an existing record
   the tooling needs the same `restage`-as-revision support programmes have: either extend
   `data:evidence restage` to `scholarships` and `cost-profiles` (write `_review.revises: true`,
   `data:promote --replace-revisions`), or add `--replace` to the two verifiers. Without it, this
   wave and any future refresh cannot stage.
2. **Page drift on `deutschlandstipendium` and `fr-excellence-major`.** The promoted records can no
   longer be re-confirmed at the bachelor level from the cited pages. Either find a page that states
   the bachelor level (a sub-page/FAQ) or let the owner re-scope the record.
3. **`stipendium-hungaricum` nationality.** The record restricts to `MA`, but no cited page names
   Morocco (it is in the sending-partner annex). The annex PDF would need to be fetched, or the
   restriction widened with the owner's decision.
4. **Scholarship deadlines need `recurringDeadline`.** `ScholarshipRecordSchema.deadline` is an ISO
   date only, so a yearless "15 July" cannot be stored as "usually". Adding `recurringDeadline`
   (as programmes have, ADR 0009) is required before most scholarship deadlines can be captured.
