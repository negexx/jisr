## 1. Slugs file — the selection rule

**Rule:** a programme is in scope when `country == "DE"` **and** its `intakes` fact holds no value (`intakes.value` is `null`/absent or an empty array). This is exactly the `intakes` column of `pnpm data:coverage --detail` (a fact "holds a value" when it is not null and, for a list, not empty).

```
pnpm data:coverage --detail --csv data-staging/de-intakes-coverage.csv --out data-staging/de-intakes-coverage.md
```

Cross-checked two ways, both agree on **39**:

- the coverage CSV (`intakes` = 0, `country` = DE) → 39;
- a direct read of `data/programs/*.yaml` (DE with `intakes.value` null/empty) → 39;
- the two slug sets are identical.

Result written to **`data-staging/de-intakes-slugs.txt`** (39 slugs).

Note vs W2: W2 wrote "39 lack intakes; 31 have a DAAD *page* (8 do not)". The 39 here is the same set; the 31-vs-8 split is the `data:daad-deadlines` tool measuring the programme *page URL*, whereas all 39 carry a DAAD-style slug (`…-daad<id>`). This wave uses the slug to seed the DAAD register page, so all 39 are read, not just the 31.

## 2. Pages (`pnpm data:pages`)

```
pnpm data:pages --slugs data-staging/de-intakes-slugs.txt --search --topics --topic-list deadline \
  --max-queries 80 --out data-staging/pages-de-deadlines.json
```

```

topic searches failed: 0 programmes kept their existing pages
no institution website: 1 programmes skipped
   slugs -> data-staging/pages-de-deadlines.json.skipped.txt
-> data-staging/pages-de-deadlines.json
```

- **Query bound (dry run first):** `at most 0 queries (cap 80); plus at most 24 topic queries`. The 24 topic queries are one `site:<institution> …Bewerbungsfrist internationale Bewerber application deadline` query per distinct institution (`--topic-list deadline`); no programme-level search was needed because every one of the 39 has a DAAD register page the tool reads by code.
- Built file: **39 programmes, 234 page URLs** (3–8 pages each). 1 programme skipped for lack of an https institution website: `de-technische-hochschule-mannheim-hrk177-international-engineerin-daad10335`.

## 4. Deadline rules applied

Two programmes yielded an intake deadline; both quotes name international applicants and both pass `verifyProposal`.

1. **`de-hochschule-fur-angewandte-wissenschaften-hrk44-international-bachelors-daad10398`** — dated:
   `applicationDeadline: 2026-09-30`
   - "Application periods The following is valid for applicants from: all countries For the winter semester: until 30 September 2026" — DAAD detail page
   - "Registration deadline for the winter term: 30 September 2026" — hs-coburg.de programme page
   - **Year stated → dated deadline** (not recurring). Audience "all countries" ✓.
   - ⚠️ **This date is already past** (2026-09-30 < 2026-10-18). The reader/verifier path has no past-date guard (`checkDeadline` only checks the quote and the year); W2's `data:daad-deadlines` tool deliberately skips past dated deadlines. Per the brief, "a verifier rejection stands" and I did not override the code — but the auditor must decide whether a closed winter-2026 deadline belongs in the next cycle's data.

2. **`de-technische-hochschule-deggendorf-hrk284-electromobility-autonomo-daad9073`** — recurring:
   `recurringDeadline: { month: 12, day: 1 }`, `applicationDeadline: null`
   - "The following is valid for applicants from: all countries 15 October - 1 December" — DAAD detail page
   - "Application period 15 October - 1 December" — th-deg.de programme page
   - **No year in either quote → recurring** `{12, 1}` ✓; audience "all countries" ✓.

No deadline was inferred from a quote without a stated year, and no recurring deadline came from a quote that states a year.

## 8. Blockers / notes for the next wave

1. **Low yield.** Only **2 of 39** programmes produced a deadline via page reading; the other 37 yielded none (or only duration/language/tuition/documents/channel facts). Raising DE coverage needs more than page-reading these DAAD-linked programmes.
2. **Past deadline.** `de-hochschule-fur-angewandte-wissenschaften-hrk44-international-bachelors-daad10398` stages `2026-09-30`, already past; the auditor must decide whether to promote it. No code guard exists on the reader path (only `data:daad-deadlines` skips past dates).
3. **14 conflict-only records** (reader value vs existing official value) are staged with a note and are **not** in the audit batch (no `preparedBy`); they change no data. Listed in the verify output; a future enrich wave could re-examine them.
4. **18 no-op revisions** were written by `restage` before `verify`; `verify` left them unchanged and the tool advises discarding them. They carry no `preparedBy` and no audit row, so `data:promote` ignores them.
5. **1 programme has no institution website** (`…mannheim…daad10335`), so it got only its register page + topic pages from no site (it is still in the pages file and was read).
6. **6 page-fetch attempts failed** during reading (logged in `calls.jsonl`); no call errored.
7. **W2's DAAD-parser blocker is unchanged**: 25/31 DAAD pages still print free-text application periods the tool refuses to parse. W2b sidesteps the parser but confirms the pages themselves rarely state an international deadline in a machine-checkable way.
