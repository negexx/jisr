# Neon Postgres + Drizzle (user data only)

- Postgres stores **user data only**: Better Auth tables, profile, saved programs, checklist state, feedback reports. Reference data (institutions, programs, routes, costs, scholarships) lives in `data/` and snapshots — never add tables for it (ADR 0003).
- Schema lives in `src/db/schema/*.ts`. Change schema → `pnpm db:generate` → commit the generated SQL in `drizzle/` → `pnpm db:migrate`. Never `drizzle-kit push` against a shared database; never edit an applied migration.
- Runtime uses the pooled connection string (`DATABASE_URL`); drizzle-kit uses the direct one (`DATABASE_URL_UNPOOLED`). Neon project stays in an EU region (Frankfurt) — GDPR.
- Better Auth tables (`user`, `session`, `account`, `verification`) are generated by `npx @better-auth/cli generate` into `src/db/schema/auth.ts`. Regenerate after changing auth plugins; don't hand-edit. `user.role` defaults to `student`.
- Rows that refer to reference data store the program **slug** plus the **snapshot version** they were saved against, not a foreign key. The UI must cope with a slug that no longer exists.
- Timestamps are `timestamptz` (UTC). Store money, if ever needed, as integer minor units + `currency char(3)`.
- Personal data (grades, nationality, language levels, budget) lives only in user-owned tables with `ON DELETE CASCADE` from `user`, so account deletion erases it (GDPR). Prefer not storing what the browser can keep.
- Use Drizzle's query API or the SQL builder; raw `sql` fragments only for Postgres features the builder lacks, always parameterised.
