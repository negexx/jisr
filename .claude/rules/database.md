# Neon Postgres + Drizzle (user data only)

- Postgres stores **user data only**: Better Auth tables, profile, saved programs (one row each), checklist ticks (one row per ticked step), feedback reports, `pending_signups` (pre-account email + consent, keyed by normalised email, expires lazily, no user FK) and `user_data_state` (one-time guest-import marker). Reference data (institutions, programs, routes, costs, scholarships) lives in `data/` and snapshots — never add tables for it (ADR 0003).
- Schema lives in `src/db/schema/*.ts`. Change schema → `pnpm db:generate` → commit the generated SQL in `drizzle/` → `pnpm db:migrate`. Never `drizzle-kit push` against a shared database; never edit an applied migration.
- Runtime uses the pooled connection string (`DATABASE_URL`); drizzle-kit uses the direct one (`DATABASE_URL_UNPOOLED`). Neon project stays in an EU region (Frankfurt) — GDPR.
- Better Auth tables (`user`, `session`, `account`, `verification`) are generated by `npx auth@latest generate` (the standalone `auth` CLI, ctx7-verified 2026-10-14) into `src/db/schema/auth.ts`. Regenerate after changing auth plugins; don't hand-edit (it is excluded from Biome for that reason). The CLI refuses a config that imports `server-only` (directly or through `@/db`), and `NODE_OPTIONS=--conditions=react-server` does not help: generate from a throwaway copy of the `betterAuth({...})` block in `server.ts` with `db`, `schema`, `sendAuthEmail`, `readPendingSignup`, `evaluateAdmission` stubbed, then delete it: `npx auth@latest generate --config <tmp>.ts --output src/db/schema/auth.ts --adapter drizzle --dialect postgresql -y`. Re-running `pnpm db:generate` afterwards must report no changes. Its timestamps are `timestamp` (no zone), a generator default; our own tables use `timestamptz`. `user.role` defaults to `student`.
- Rows that refer to reference data store the program **slug** plus the **snapshot version** they were saved against, not a foreign key. The UI must cope with a slug that no longer exists.
- Timestamps are `timestamptz` (UTC). Store money, if ever needed, as integer minor units + `currency char(3)`.
- Personal data (grades, nationality, language levels, budget) lives only in user-owned tables with `ON DELETE CASCADE` from `user`, so account deletion erases it (GDPR). Prefer not storing what the browser can keep.
- Use Drizzle's query API or the SQL builder; raw `sql` fragments only for Postgres features the builder lacks, always parameterised.
