# next-intl (fr / en / ar)

- Locales: `fr` (default), `en`, `ar`. Routing config, navigation helpers and request config live in `src/i18n/`; `src/proxy.ts` runs `createMiddleware(routing)` and exports it as `proxy`.
- Every key exists in all three `messages/*.json` files. Add to all three in the same change; if an `ar` translation isn't ready, put the `fr` text with a `TODO-translate` marker rather than omitting the key.
- Namespace keys by page/component (`matches.card.status.satisfied`). Use ICU placeholders/plurals — never concatenate translated fragments.
- `ar` renders with `dir="rtl"`. Keep Latin-script proper nouns, URLs, currency codes and numbers readable inside RTL text (wrap in `<bdi>` where they can flip punctuation).
- Do not translate official names: university and program names, exam and document names (e.g. Baccalauréat, official portal names). Show the original and add a short gloss.
- The product ships in exactly three languages: English, French, Modern Standard Arabic. No Darija (no variant, no fourth locale). Explanatory copy in every language should be plain and short, written for a school-leaver rather than in administrative jargon; adding any other locale needs an ADR.
- Data text falls back to `fr` when the locale's translation is missing; a `draft` (machine-assisted) translation shows a small "translated automatically" note until reviewed. UI strings come from `messages/*.json`; data text from snapshot text shards (one per locale).
- ICU contract: every displayed argument is a string already formatted for the locale (`formatNumber`, `formatMoney`, `formatDate` from `src/lib/format.ts`; money and grades come back without bidi marks). A number is passed only as a plural or select selector, never displayed through `#` or a numeric argument, because ICU would print Arabic-Indic digits in `ar`. Plural messages therefore take `{n}` (selector) and `{count}` (the formatted string). Wrap displayed Latin names, amounts and dates in `<bdi>` in `ar`.
- Vocabulary and wording tests: `src/lib/i18n/vocabulary.ts` holds runtime arrays of every reason code, kind, route outcome and so on, with a type-level exhaustiveness check and `MESSAGE_ARGS` (the ICU arguments per key); `tests/i18n/vocabulary.test.ts` requires every key in all three catalogues with matching placeholders. `tests/i18n/forbidden-wording.ts` and `trust-wording.ts` ban eligibility/guarantee words and require that "official" never appears in estimate or guidance wording, that `ar` differs from `fr`, and that fr has a non-breaking space before `: ? ! ;`. Each page namespace has a messages test (`profile-messages`, `matches-messages`, `component-messages`, `program-messages`); add yours when you add a namespace.
- Arabic terms: الإجازة for the Bachelor's degree, العلامة for a grade; Latin digits. Machine-drafted `ar` copy is reviewed by a native speaker before launch (review lists are kept in the task reports; do not mark strings `TODO-translate` unless the key is genuinely untranslated).
- Server Components use `getTranslations`; client components use `useTranslations`. Prefer passing strings from the server to keep client bundles small.
